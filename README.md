# 拾光记账 · 网页版

一个可以自行部署的中文记账 PWA。支持 iPhone、Mac 和其他现代浏览器；首次联网缓存完成后，可以离线打开、记账和查看统计。

这是纯静态网站，不需要服务器程序、数据库服务、API Key 或登录系统。账本保存在使用者当前浏览器的 IndexedDB 中，静态托管平台只提供网页文件。

## 下载后直接部署

1. 在仓库页面点击 **Code → Download ZIP**，解压下载的源码包。
2. 找到里面的 **`dist` 文件夹**。这是已经构建好的网站，不需要安装开发工具。
3. 将 `dist` 文件夹的内容上传到支持 **HTTPS** 的静态网站托管服务。网站的发布根目录应直接包含 `index.html`、`sw.js` 和 `icons` 文件夹。
4. 打开你自己的部署网址，在「设置」中确认 **离线缓存已就绪**。

**不要把整个 GitHub 源码 ZIP 当作网站上传，也不要只上传一个 HTML 文件。** 部署服务需要的是 `dist` 中的完整文件。

### Cloudflare Pages 手动上传

1. 登录自己的 Cloudflare 账户，进入 **Workers & Pages**，创建 Pages 项目，选择上传静态文件（界面名称可能为「拖放文件 / Drag and drop」）。
2. 填写自己喜欢的项目名称，上传 `dist` 文件夹或其中的全部内容，完成部署。也可以在本机构建后上传生成的 `shiguang-ledger-static.zip`。
3. 使用平台分配给自己的 HTTPS 地址访问。
4. 以后更新时，在同一 Pages 项目中新建生产部署，上传新的完整 `dist`。

首次创建时选择 Direct Upload 的项目，之后若要改用 Git 自动部署，需要另外创建 Git 集成项目。具体入口见 [Cloudflare 官方 Direct Upload 文档](https://developers.cloudflare.com/pages/get-started/direct-upload/)。

### Cloudflare Pages 连接 Git 仓库

Fork 本仓库到自己的账户，再创建 Pages 项目连接自己的仓库：

| 设置项 | 值 |
| --- | --- |
| 框架预设 | None |
| 构建命令 | 留空；直接发布仓库中已构建的文件 |
| 构建输出目录 | `dist` |
| 生产分支 | `main` |

修改源码后，先在本机运行 `python3 scripts/build.py`，将更新的 `web` 和 `dist` 一起提交，再由 Pages 发布。

### 其他静态托管平台

Netlify、Vercel 或自己的静态服务器也可以使用：发布目录设为 `dist`，使用 HTTPS，关闭额外的打包和重写操作。必须正确提供 `.mjs` 文件的 JavaScript MIME 类型（例如 `text/javascript`），不能将脚本请求统一重写成 HTML。

可以部署在网站根目录，也可以放在独立子目录。子目录地址请以 `/` 结尾。应用资源、Manifest 和 Service Worker 使用相对路径。推荐一个域名只部署一个实例；同一来源下的多个实例会共享同名本地数据库，并不适合作为相互隔离的账本。

`_headers` 为支持该配置的托管平台提供缓存和安全响应头；其他平台可按自己的方式设置。建议 HTML 不长期缓存、`sw.js` 设置 `Cache-Control: no-store`，避免 CDN 强制缓存旧版。Service Worker 应位于应用目录内。

## 手机安装与离线使用

1. iPhone 使用 **Safari** 打开自己的 HTTPS 网址。
2. 点击「分享 → 添加到主屏幕」。若有「作为网页 App 打开」开关，请开启。
3. 从主屏幕图标打开应用，保持联网，进入「设置」确认离线缓存已就绪。
4. 此后可以断网打开、保存流水、管理分类和查看统计。首次访问、下载新版本仍需要网络。

这不是签名安装的 iOS 应用，不需要每七天重新安装。不要直接双击 `index.html` 以 `file://` 方式使用；这种方式不能正常启用离线能力。

## 日常使用

- **记一笔**：选择支出或收入，输入金额；先点一级分类，再点二级分类，也可以选择「不细分」，填写日期和备注后保存。
- **流水**：切换账本，筛选和搜索记录；可以编辑或删除流水。
- **统计**：按日、周、月、季度、年查看收支，支持一级、二级分类统计。
- **账本与分类**：新增账本和分类，修改名称及图标；进入分类整理模式后拖动排序、调整父级，或通过点击选择和放置。已有流水使用的分类不能直接删除。
- **示例模式**：提供程序生成的虚构记录，只在内存中体验，不写入正式账本。首次正式使用时没有预装的交易记录。
- **备份**：在「设置」中导出完整 JSON 并保存到设备外部位置。CSV 用于表格分析，不能恢复账本。
- **导入**：有效的版本 1 完整备份会作为新账本导入，保留现有账本；重复导入会新增一份。也支持兼容格式的 Mac 版备份，但本仓库不包含原生 Mac 应用。
- **更新**：托管文件更新后，联网进入「设置 → 检查更新」，出现提示后点击「更新并重新打开」。编辑中的内容请先保存。

## 数据保存范围

账本不上传至网站服务器，没有账户登录、云同步或多人共享。不同设备、浏览器及不同网站地址通常拥有各自的本地数据。Safari 页面和主屏幕 App 的存储行为也可能受系统版本影响，使用哪个入口就在哪个入口备份。

应用保留最近 30 次写入前的本地快照，并在恢复操作前保留原数据。快照与账本在同一浏览器中，清除网站数据、卸载、更换设备或浏览器回收存储都可能导致丢失。**离线缓存保存的是程序文件，不等于账本备份。** 请定期导出完整 JSON。迁移域名或设备时，先从旧地址导出，再到新地址导入。

## 修改源码与本机运行

构建只需要 **Python 3.9 或更新版本**，使用标准库，不需要 npm 安装。下面的命令在解压后的仓库目录运行；Windows 可以将 `python3` 替换为 `py -3`。

```sh
python3 scripts/build.py
python3 scripts/preview.py
```

浏览器打开终端显示的本机链接（默认 `http://127.0.0.1:8080/`）。按 `Ctrl+C` 停止预览。远程手机无法通过自己的 `127.0.0.1` 访问电脑；手机安装和离线验收请使用部署后的 HTTPS 地址。

构建会重新生成 `dist` 和 `shiguang-ledger-static.zip`。文件内容决定构建编号，样式和模块带版本指纹，Service Worker 按版本缓存完整应用。修改后应重新构建，完整替换网站文件，不能混用不同构建的文件。

开发检查需要 Node.js 22 或更新版本，无第三方测试依赖：

```sh
node --test tests/*.test.mjs
python3 scripts/check-build.py
```

| 路径 | 用途 |
| --- | --- |
| `web/` | HTML、CSS、JavaScript、Manifest、Service Worker 和图标源码 |
| `dist/` | 可直接上传的静态网站 |
| `scripts/build.py` | 按固定文件清单构建，不读取账本或备份 |
| `scripts/preview.py` | 仅绑定本机的预览服务 |
| `scripts/check-build.py` | 构建完整性和源码一致性检查 |
| `tests/` | 金额、分类、导入、统计和离线导航测试；数据由程序生成 |

## 常见问题

**页面空白、脚本加载失败**：确认发布根目录包含 `index.html`，上传了全部 `dist` 文件，`.mjs` 的响应类型是 JavaScript，控制台没有 404 或 HTML 被当作脚本的错误。

**离线缓存未就绪**：使用 HTTPS 或本机 localhost，先联网完整打开一次，检查托管服务没有漏传图标、模块或 `sw.js`。普通局域网 HTTP 地址无法启用 Service Worker。

**部署了新版仍显示旧版**：先保存编辑内容，再检查更新；若无提示，检查平台是否将旧 `sw.js` 长期缓存。不要为了更新程序直接清除网站数据，这会删除本地账本。

**换网址后账本不见了**：新网址有独立存储，回到旧网址导出完整 JSON，再到新网址导入。
